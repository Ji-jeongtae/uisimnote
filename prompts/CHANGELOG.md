# 분류 프롬프트 변경 기록

프롬프트 원문은 `lib/prompt.js`의 `SYSTEM_PROMPT`이고, 버전은 `PROMPT_VERSION`에 적는다.
실제 Gemini 실행 결과는 `prompt-log/`에 날짜별 JSON으로 남는다(`node scripts/run-prompt.mjs`).

---

## 현재 앱 사용 버전: v3 (2026-11-19 결정)
v4는 유형 일치 동일(80%), 3회 일관성 하락(8/10→6/10)으로 앱에는 v3 사용. v4 프롬프트는 `lib/prompt.js`의 `PROMPTS.v4`로 보관.

---

## v4 — 2026-11-19 (보관, 앱 미사용)

**목적**: 2단계 힌트 카드("이런 문장은 확인하고 써야 해요")의 'AI는 이렇게 틀려요'와 분류 기준을 맞춘다. 학생이 보는 설명과 모델이 쓰는 유형 정의가 같은 말을 하게 한다.

**근거**
1. Huang, L. et al. (2025). A Survey on Hallucination in Large Language Models: Principles, Taxonomy, Challenges, and Open Questions. *ACM Transactions on Information Systems*, 43(2). — 사실 오류(사실 불일치·지어냄)와 시점이 지난 정보 등 환각 분류 → 통계·수치, 날짜·법령, 최신 동향 설명.
2. Walters, W. H., & Wilder, E. I. (2023). Fabrication and errors in the bibliographic citations generated by ChatGPT. *Scientific Reports*, 13, 14045. — 지어낸 인용과 실존 인용의 서지 오류 → 논문·책 인용 설명.
3. Wineburg, S., & McGrew, S. (2019). Lateral reading and the nature of expertise: Reading less and learning more when evaluating digital information. *Teachers College Record*, 121(11). — 요약·2차 자료가 아니라 원 출처로 가서 확인(측면 읽기) → '이렇게 확인해요'와 인물·기관 발언 설명.

**바뀐 문장** (`lib/prompt.js`의 `[유형]` 블록만. 절대 규칙·인용 우선 규칙·검색어 규칙·sites 목록 제한은 v3 그대로)
- 추가: "각 유형 옆의 'AI가 틀리기 쉬운 방식'은 왜 그 유형을 확인해야 하는지에 대한 설명이다. 입력 문장이 실제로 그렇게 틀렸는지는 판단하지 말고, 유형을 고르는 데만 쓴다."
- 유형마다 한 줄씩 추가:
  - 통계·수치: 그럴듯한 숫자를 만들어 내거나 다른 조사의 숫자를 옮겨 적는다.
  - 날짜·법령: 바뀌기 전의 날짜·제도를 지금 것처럼 말한다.
  - 논문·책 인용: 없는 논문을 지어내거나 있는 논문의 저자·학술지·연도를 틀린다.
  - 인물·기관 발언: 말한 사람이나 기관을 바꿔 적는다. (설명에 "회사·기관이 발표·소개했다는 내용" 포함)
  - 인과관계: 원인 하나로 단정한다. / 일반화: 근거 없이 넓게 말한다. / 최신 동향: 지난 정보를 지금 것처럼 말한다.
- 참고(info) 설명에 "학생에게 하는 조언" 포함.
- 유형마다 예시 표현(%, ○명 / "~가 밝혔다" / 저자(연도) 등)을 붙였다.

**실행 기록**: `prompt-log/2026-11-19T12-08-45_eval-summary.md` (gemini-2.5-flash, v3·v4, 참가자 A 정답표 10문장 + 시연 10문장, 각 3회 = 12회).
- 참가자 A(정답표): 유형 일치 v3 80% / v4 80%, 단계 일치 70% / 70%, 판정 표현 0 / 0건. 3회 일관성(유형 묶음까지) 8/10 → 6/10, 단계만 10/10 → 10/10.
- 시연(수기 예시 대비, 정답표 아님): 93% → 97%, 판정 표현 0 / 0건.
- 두 버전 모두 같은 3문장(정답표 7·9·10)을 틀림. **v4가 나아졌다는 근거는 아직 없다**(표본 작음). 학생 화면 문구와 기준을 맞추는 목적으로 유지할지 따로 결정.

## v3 — 2026-11-19 (실제 Gemini 실행 기록 없음 — 확인 필요)

**문제** (정태 요청): '믿을 만한 곳에서 찾기'가 매체 유형(academic/statistics)으로만 정해져 RISS·Scholar·KOSIS밖에 안 나옴. 기업 실적·영화 관객 수·수상 사실처럼 학술 DB가 맞지 않는 문장에도 같은 곳을 보여 줌.

**수정**
- 출력 필드 `sites` 추가: 문장마다 확인하기 좋은 곳을 **우리가 정한 목록(`lib/sites.js`)의 key로만** 0~3개 고른다. 목록: riss, scholar, kci, nl, kosis, law, korea, dart, kobis, bigkinds. 스키마 enum으로 강제.
- 출력 필드 `official` 추가: 문장에 나오는 회사·기관의 공식 사이트 {name, domain} 0~2개. 확실할 때만.
- 링크 주소는 모델이 쓰지 않고 앱이 만든다(사이트 자체 검색 또는 Google `site:도메인 검색어`). 모델이 없는 URL을 지어낼 수 없게 하려는 것. 절대 규칙 3(출처 URL 생성 금지)과 맞춤.
- 서버 보정: 목록에 없는 key 버림, domain은 `https://`·`www.`·경로를 떼고 형식 검사, 목록에 이미 있는 도메인은 official에서 뺌.
- 예시 2개에 sites/official 추가.
- 앱: AI 답변에 그 문장의 출처 링크(URL·DOI·각주 [n])가 있으면 검색어 자리에 **그 링크를 그대로** 보여 준다.

**확인 필요**: v3로 실제 Gemini를 아직 한 번도 돌리지 않았다(무료 키 보호). `examples/participant-a.json`, `demo.json`의 sites/official은 손으로 넣은 더미. 실제 실행 시 official 도메인이 맞는지 따로 확인할 것.

## v2 — 2026-11-19

**입력 예**
> 2023년 Nature에 실린 Walters와 Wilder의 연구는 ChatGPT가 만든 학술 인용 636건을 검증했습니다.

**문제**
1. **검색어 잘림**: 검색어 칩이 문장 앞부분을 그대로 잘라 만들어졌다(예: "2023년 Nature에 실"). 이렇게 검색하면 문헌이 찾아지지 않는다. 학술지명(Nature)처럼 학생이 검증해야 할 값이 검색어에 들어가 AI의 주장을 그대로 확인하는 검색이 되었다.
2. **인용 → 날짜·법령 오분류**: 논문을 언급하는 문장이 연도("2023년") 때문에 '날짜·법령'으로 분류되었다. 학생이 확인할 곳이 학술 DB인데 유형 표시가 이를 가렸다.
3. 한 문장에 유형이 여러 개(인용 + 수치)여도 하나만 표시되었다.

> 확인 필요: 위 문제는 Gemini 키를 설정하기 전 **로컬 화면 점검(MOCK 분류)** 에서 발견했다. v1 프롬프트를 실제 Gemini로 실행한 결과가 아니다. v1·v2를 같은 입력으로 실제 실행해 비교한 기록을 `prompt-log/`에 추가할 것.

**수정**
- 출력 필드 `type`(1개) → `types`(배열). 해당하는 유형을 모두 넣고 가장 중요한 것을 맨 앞에 둔다.
- **인용 우선 규칙** 추가: 논문·연구·보고서·책·학술지를 언급하는 문장은 연도가 있어도 '논문·책 인용'을 맨 앞에 둔다. '날짜·법령'은 사건·제도·법령의 시점 자체가 주장일 때만 쓴다. 예시 2개 추가.
- **검색어 규칙** 추가: 2~3개, 저자·기관·주제 중심. 학술지명·수치·사건 날짜는 넣지 않는다. 문장 앞부분을 잘라 쓰지 않는다. 나쁜 예 1개 추가.
  - 해석: 문헌을 찾기 위한 저자 + **발행 연도**는 허용한다(지시 예시 "Walters Wilder 2023 ChatGPT citations"를 따름).
- 서버 보정(`normalize`): 단계(level)를 유형 표로 다시 계산해 유형과 단계가 어긋나지 않게 함. 문장 앞부분을 그대로 자른 검색어(8자 이상)는 버림.

- 절대 규칙: 참·거짓 판정 금지, 정답 제시 금지, 출처 생성 금지, 모든 문장에 하나씩 결과.
- 온도 0, JSON 스키마 강제.
